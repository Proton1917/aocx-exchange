## 1. 目的与层次

AOCX 在不同 Agent、任务和工具之间传递可继续工作的上下文。核心提供对象身份、版本、关系、来源和内容容器；领域规则由可独立演进的 profile 描述。代码、数学、文档、数据和自由探索共享这层容器。

四层职责：现有 MCP、文件或函数调用负责运输；AOCX 记录对象与关系；领域 profile 解释专业字段；编码 profile 提供 JSON、紧凑表格或模型中心语言视图。参考实现采用本地命令行及 Python 函数，薄 Skill 按需选择操作。

“必须”用于独立实现之间的可验证契约。自由探索的内容、语言和领域词汇保持开放。机器检查针对声明的契约；领域正确性由相应证据与评估方法处理。

## 2. 自由内容与最小记录

记录是 UTF-8 JSON 对象，至少含四个字符串：

| 字段 | 含义 |
|---|---|
| `id` | 当前 `namespace` 内稳定的对象标识 |
| `rev` | 不可变修订标识；引用指明该值 |
| `kind` | 开放的对象种类，支持领域限定名 |
| `text` | 任意自然语言、公式、伪代码、混合语言或探索性表达 |

```json
{"id":"idea-7","rev":"1","kind":"exploration","text":"尝试把反射相关写成带符号核；先找一个可计算的有限例子。"}
```

常见种类有 entity、claim、task、method、decision、evidence、source、artifact、term、question。新领域可使用 `chemistry/reaction`、`editorial/section` 等名字。核心保留未知种类与未知字段。

可选字段：`body` 保存领域结构；`state` 保存状态；`conditions` 保存条件；`scope` 保存范围和量词；`provenance` 保存来源；`anchors` 保存需要逐值保留的信息；`extensions` 保存扩展元数据。原始数据与全量编码保留这些值；投影必须声明省略范围。

JSON 成员名不得重复，NaN 等非有限数值不属于交换数据。跨语言精确数值宜使用十进制字符串或表达式对象，数量同时记录单位。缺失字段和显式 null 分别保留。

## 3. 条件、状态和关系

`state.work` 描述工作进度，例如 active、complete、blocked。`state.knowledge` 描述证据状态，例如 assumed、reported、observed、derived、checked、refuted、open。维度独立，词汇可扩展。实验完成可以同时报告失败结果，derived 可以与额外条件并存。核心保持这些声明，不自动改变结论状态。

条件项为：

```json
{"text":"P 在指定参数范围内成立","ref":{"id":"P","rev":"2"}}
```

`text` 为完整条件表述，`ref` 可选。引用固定前提修订。选取上下文时保留前提及继承条件。探索记录可以省略条件；正式推导的完整性由所选领域 profile 检查。

关系必需字段为 `id`、`from`、`to`、`kind`。端点均为 `{id,rev}`，其余字段保留。关系方向：

| kind | 方向与含义 |
|---|---|
| depends_on | 使用者 → 前提 |
| assumes | 条件结论 → 假设 |
| supports | 证据 → 被支持记录 |
| cites | 引用者 → 来源 |
| relates_to | 原表达中的有关对象 → 关联对象 |
| uses | 工作或方法 → 使用对象 |
| produces | 工作或方法 → 有来源依据的产物 |
| blocks | 阻碍因素 → 受阻工作 |
| supersedes | 新修订 → 同一对象的旧修订 |

依赖存在不改变证据状态。普通关系图允许环；修订继承必须无环。数学 profile 可另加证明依赖无环规则。

## 4. 修订与冲突

同一 `(namespace,id,rev)` 标识同一不可变记录。内容变化采用新修订。快照以 `heads` 明确选择当前修订；时间戳记录时间，不裁决冲突。

三方合并检查使用共同基线 B、左快照 L、右快照 R。L/R 选择同一修订时相容；一方与 B 相同时，另一方变化可成为候选；两方都离开 B 且选择不同修订时报告冲突。同一记录身份对应不同内容或同一关系 ID 对应不同关系，也构成冲突。参考实现给出检查结果，宿主负责合并和写入。

来源保存原始格式、路径、可选行号及原档案身份。导入器保留原字节，同时生成可查询投影。未知原字段继续保存在投影 body 或原档案中。

## 5. 档案与资源

入口是 `aocx.json`，`records.jsonl` 每行一条记录，`relations.jsonl` 每行一条关系。资源清单记录相对路径、精确字节数、SHA-256 和角色。摘要针对已存储字节；重新序列化后重新计算。

| 入口字段 | 内容 |
|---|---|
| format / version | AOCX / 1.0 |
| namespace | 对象标识的作用域 |
| records / relations | 两个 JSONL 相对路径 |
| heads | ID 到当前修订的映射 |
| profiles | 使用的 profile 标识 |
| required_profiles | 声明的语义操作必须理解的 profile |
| assets | 已包含文件、摘要、字节数和角色 |
| origins | 原始格式、原始资源文件与根路径 |
| external_resources | 可选外部位置、版本和可用性 |
| extensions | 可选扩展元数据 |

角色区分正文、附件、索引、原始档案与视图。完整源码和源码索引分别登记。外部资源明确写 availability:external 或缺失状态，链接不会改变其字节包含范围。

目录可 ZIP 封装。读取端拒绝绝对路径、父目录跳转、符号链接和冲突条目，并设置文件数与展开体积上限。外部取回与程序执行由宿主另行决定。

## 6. 紧凑视图

JSONL 是完整基线。`table-jsonl/1` 将重复字段名放入头部，以有说明的列顺序编码。头部记录版本、命名空间、源记录及关系文件摘要、投影模式、列定义、选择的固定修订、记录/关系数量和省略范围。

```json
["record","idea-7","1","exploration","尝试反射核的有限例子",{}]
```

最后一个对象存其余字段。关系行依次为种类标记、关系 ID、起点、关系类型、终点、其余字段。

full 模式保留全部 JSON 值和未知字段，可恢复相同数据模型。handoff 模式保留完整 text、条件、范围、状态、来源和 anchors；省略 body/extensions 时在头部声明。它绑定完整源数据的摘要。

选取对象时递归保留引用条件，以及 depends_on、assumes、cites 所需记录。省略其他关系的数量明确声明。确定性视图完整保留原文字；语义改写属于单独语言 profile。

## 7. 扩展与协商

能力声明包含 versions、profiles、codecs、可选 required_profiles、accepts_lossy。双方从交集选择表示。基线使用 JSONL，共同支持时可用表格编码；语义视图还需指定读者与任务的评估证据。

未知可选字段/profile 原样保留。未知必需 profile 使相应语义操作返回 unsupported，保存模式仍可保留数据。核心检查、领域检查和语言评估分别报告。双方可通过匹配的 `codec_modes` 声明注册外部编码的 lossless/semantic 模式；选中外部编码时结果标明需要宿主实现，semantic 还要求双方接受语义压缩。

新 profile 声明：标识/版本、适用对象、附加字段含义、关系方向、保护信息、检查方法、依赖、输出范围、回退表示和测试向量。可选 JSON Schema 随本地资源提供；检查器由宿主明确注册。扩展声明不自行执行程序。

同一主版本保持已有字段含义。改变已有字段语义或关系方向时，使用新主版本或新限定名称。初始参考实现支持 1.0，其他版本由能力声明决定。

## 8. 实现边界

`scripts/aocx.py` 实现创建、AOCI/GBCX 导入、原字节恢复、验证、紧凑视图、能力匹配、语言视图检查和三方冲突检查。通过 Python 标准库运行，无常驻服务。现有 AOCI MCP 由宿主继续调用。

程序检查数据契约、引用、修订、条件闭包及哈希。参考实现按 Python JSON 规则读取数值：整数使用 Python 整数，小数使用有限浮点数；逐数字精度通过字符串/表达式对象及原始字节保存。领域结论和模型理解能力使用独立证据。执行记录在 `assets/validation/`，论文实验与本实现的验证分开标注。
